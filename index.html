Exam topics

Skills measured in the January 2026 GH-900 exam blueprint.

7 topics
Core

Git and GitHub basics

Understand why version control matters, how Git differs from GitHub, and how commits, branches, accounts, organizations, GitHub Flow, and Markdown fit together.

Key items
  • Version control: Tracks changes over time, supports recovery, and lets contributors work safely in parallel.
  • Git versus GitHub: Git is the distributed version-control system; GitHub hosts Git repositories and adds collaboration services.
  • Repositories, commits, and branches: Repositories hold project history, commits record snapshots, and branches isolate lines of work.
  • Account structures: Distinguish personal accounts, organizations for teams, and enterprise options for centralized governance.
  • GitHub Flow: Create a branch, make commits, open a pull request, review, merge, and deploy.
  • Markdown: Format README files, issues, pull requests, comments, tables, task lists, links, and code blocks.
  • Desktop and Mobile: Use GitHub Desktop for visual Git workflows and GitHub Mobile for notifications, reviews, and lightweight collaboration.
25–30% of exam
Core

GitHub repositories

Know repository structure and key files, then learn how templates, branches, files, insights, stars, metrics, and dependency views support healthy maintenance.

Key items
  • Key repository files: README explains the project, LICENSE defines use, CONTRIBUTING sets contribution rules, CODEOWNERS assigns reviewers, and SECURITY explains vulnerability reporting.
  • Create and organize: Start from scratch or a template, choose visibility, and use branches to separate stable and in-progress work.
  • Manage files: Create, edit, rename, move, and delete files through GitHub or a local Git workflow.
  • Repository visibility: Use insights, stars, feature previews, metrics dashboards, and dependency views to understand health and reach.
  • Maintenance: Keep documentation current, use clear naming, review dependencies, archive inactive work, and establish contribution standards.
10–15% of exam
Workflow

Collaboration with GitHub

Use issues, pull requests, discussions, notifications, templates, and assignments to coordinate work, plus Gists, Wikis, and Pages to share knowledge.

Key items
  • Issues, pull requests, and discussions: Track work with issues, propose code changes with pull requests, and hold open-ended community conversations in discussions.
  • Connected work: Link pull requests to issues for automatic closure, and use templates, filters, labels, and assignees to keep work consistent.
  • Notifications: Watch repositories or threads and tune notification settings so important activity reaches the right inbox.
  • Knowledge sharing: Use Gists for snippets, Wikis for repository documentation, and GitHub Pages for hosted static sites.
10–15% of exam
Platform

Modern development practices

Recognize how Actions automates workflows, Copilot assists development, and Codespaces, dev containers, and github.dev provide cloud-based coding environments.

Key items
  • GitHub Actions: Automates CI/CD and repository tasks with event-triggered workflows made of jobs and steps.
  • GitHub Copilot: Provides AI-assisted code suggestions, chat, agents, Agent Mode, and a choice of supported models.
  • Copilot plans: Understand how individual, Business, and Enterprise offerings differ in licensing, policy control, and organizational context.
  • Codespaces: Supplies configurable cloud development environments that can be standardized with dev container configuration.
  • github.dev: Offers a lightweight browser editor for quick changes, while Codespaces includes compute, terminals, and a full development environment.
10–15% of exam
Workflow

Project management

Organize work with GitHub Projects, views, labels, milestones, workflows, assignees, and saved replies, then use insights to assess progress.

Key items
  • Projects and layouts: Track issues, pull requests, and draft items in table, board, or roadmap views.
  • Organization tools: Use custom fields, labels, milestones, filters, and built-in workflows to classify and automate work.
  • Efficient communication: Assign owners to clarify responsibility and use saved replies for consistent, repeatable responses.
  • Project insights: Build charts from project data to monitor progress, workload, trends, and productivity.
5–10% of exam
Platform

Privacy, security, and administration

Secure accounts with 2FA or passkeys and understand permissions, roles, visibility, branch protection, teams, EMUs, and organization-wide Copilot policies.

Key items
  • Account protection: Use two-factor authentication and passkeys to reduce the risk of password-based account compromise.
  • Permissions and roles: Know common repository and organization roles and grant only the access each person needs.
  • Enterprise controls: Enterprise Managed Users centralize identity lifecycle, while Copilot policies control feature availability across organizations.
  • Privacy and protection: Choose public, private, or internal visibility and use branch protection rules to enforce review and status-check requirements.
  • Organization administration: Manage settings, teams, membership, repository access, and role assignments at organization scope.
10–15% of exam
Community

The GitHub community

Learn how open source, Sponsors, following, Marketplace, InnerSource, forks, templates, and discoverability help people share and sustain software.

Key items
  • Open source and Sponsors: Open development enables reuse and collaboration, while Sponsors provides financial support to maintainers.
  • GitHub's role: Hosting, collaboration, discovery, automation, and security features help open-source projects grow and operate.
  • Following: Follow people and organizations to see their public activity and discover relevant work.
  • GitHub Marketplace: Find apps and Actions that extend GitHub workflows and integrate external services.
  • InnerSource: Apply open-source collaboration practices inside an organization while keeping repositories private or internal.
  • Reuse and discovery: Fork repositories to contribute independently, use templates to standardize new projects, and improve metadata so repositories can be found.
5–10% of exam

Git command reference

GH-900 tests foundational Git concepts more than command memorization. These commands cover the practical workflows associated with the exam objectives.

Setup and help

git --version
Display the installed Git version.
git config --global user.name "Your Name"
Set the author name used for commits on this computer.
git config --global user.email "you@example.com"
Set the email associated with new commits.
git config --list
Review effective Git configuration values.
git help <command>
Open detailed help for a Git command, such as git help commit.

Create and connect repositories

git init
Initialize a new local Git repository in the current folder.
git clone <repository-url>
Download a remote repository, its files, branches, and history.
git remote -v
List configured remote names and their fetch and push URLs.
git remote add origin <repository-url>
Connect the local repository to a remote named origin.

Inspect and record changes

git status
Show the current branch and staged, modified, or untracked files.
git add <file>
Stage one file for the next commit.
git add .
Stage all current changes beneath the working directory.
git diff
Display unstaged changes in the working tree.
git diff --staged
Display changes already staged for the next commit.
git commit -m "message"
Create a commit from staged changes with a concise description.
git rm <file>
Remove a tracked file and stage its deletion.
git mv <old> <new>
Move or rename a tracked file and stage the change.

Review history

git log
Display commit history with author, date, and message details.
git log --oneline --graph --decorate
Show a compact visual history of branches, merges, and references.
git show <commit>
Inspect one commit and the changes it introduced.
git blame <file>
Show the last commit and author responsible for each line.

Branches and merging

git branch
List local branches and identify the current branch.
git branch <branch-name>
Create a branch without switching to it.
git switch <branch-name>
Switch to an existing branch.
git switch -c <branch-name>
Create a new branch and switch to it.
git checkout <branch-name>
Common older syntax for switching branches; git switch is clearer for this task.
git merge <branch-name>
Integrate the named branch into the current branch.
git branch -d <branch-name>
Delete a local branch after Git confirms its work has been merged.

Synchronize with GitHub

git fetch origin
Download remote commits and references without merging them.
git pull origin main
Fetch the remote main branch and integrate it into the current branch.
git push origin <branch-name>
Upload a local branch and its commits to GitHub.
git push -u origin <branch-name>
Push a branch and set its upstream so later git push and git pull commands can omit names.

Undo and pause work

git restore <file>
Discard unstaged changes in a working-tree file.
git restore --staged <file>
Unstage a file while preserving its working-tree changes.
git revert <commit>
Create a new commit that safely reverses an earlier commit.
git reset --soft HEAD~1
Move the branch back one commit while keeping the changes staged.
git reset --hard HEAD~1
Destructive: move back one commit and discard matching staged and working-tree changes.
git stash
Temporarily save uncommitted tracked changes and clean the working tree.
git stash pop
Reapply the latest stash and remove it from the stash list if successful.

Tags and releases

git tag
List tags that mark important points in repository history.
git tag -a v1.0 -m "Version 1.0"
Create an annotated tag with a message.
git push origin v1.0
Publish a specific tag to GitHub.
